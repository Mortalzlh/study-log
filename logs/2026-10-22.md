## 卡住的地方

**1）同一天栽了两次「少一个空格」，两个后果完全不同。**

- `grep -c " 500 "access.log`（引号和文件名之间少空格）→ bash 把 `" 500 "access.log` 当成**一个**参数，于是命令行里**没有文件名了**，grep 转过去读标准输入，光标停住不动，看着像卡死
- `sudo chown$USER:$USER s.sh`（`chown` 后面少空格）→ bash 把整串当命令名去找，报 `command not found`。**这条才是真麻烦：它没执行成功，但也不影响我继续敲别的命令，所以我一直到复查才发现 `s.sh` 的属主还是 `root:root`**

结论两条：**空格是分隔符，少一个就变成另一个词**；以及**改权限之后必须 `stat -c '%a %U:%G %n' 文件名` 复验**，不能凭「我敲过了」就认为生效。

**2）`sed -i.bak` 没做成，但顺手验证了一件重要的事。**

任务单要求预览确认后再用 `-i.bak` 真改文件。我把说明里的 `-i.bak` 当命令单独敲了两遍，报 `command not found`，主数据没动。事后复查：`md5sum access.log` 还是 `5fa34e6188cbb82d95c4b4d59f64488a`，`wc -l` 还是 10000。昨天污染 `access.log` 的教训起作用了——**`-i` 这种原地改写一律先在副本上做**：`cp access.log t.log` 再对 `t.log` 动手。

**3）`awk '$7>500 {print $7}'` 输出空，一点错都不报。**

`$7` 是请求路径（字符串），拿它跟 500 比，awk 把字符串转成数字得到 0，条件永远不成立，于是**安静地返回空**。改成 `awk '$9>=500'` 才有结果。这比报错危险：报错会逼你停下来查，空结果会让你以为「今天日志里没有异常」。所以处理任何日志前先 `awk 'NR==1{print NF}'` 确认字段数。

**4）`tail -20 ~/.python_history` 我在 `>>>` 里敲了一次。**

提示符 `>>>` 说明还在 Python 里，`$` 才是 shell。在 Python 里敲 shell 命令只会得到 `NameError`。想查自己刚才在解释器里敲过什么，`~/.python_history` 这个文件是累积写的，退出 Python 后才更新——Python 还开着的时候看不到最新几行。
