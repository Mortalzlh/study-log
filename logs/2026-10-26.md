## 卡住的地方

**1）`curl -x POST` 小写 `-x` 是代理，不是请求方法。**

`-x` = 指定 proxy，`-X` = 指定 HTTP method，curl 的选项大小写是两个完全不同的东西。改成 `-X POST` 才对。这类坑在 `ss`、`tar` 上也有，记住「大写字母一般是改变行为方向，小写是带参数」。

**2）`curl -s -o f.json https://api.example.com/data` 一个文件都没生成。**

`api.example.com` 是任务单里的**占位符**，这个域名根本不存在，curl 解析失败，`-o` 的目标文件也就不会被创建。我在整个 home 里 `find -name '*.json'` 结果为空。以后凡是文档里的 `example.com`、`localhost:8080`、`<your-token>`，先换成一个真实可达的地址再测。

**3）`kill 8000` —— 我把端口号当进程号杀了。**

8000 是端口，不是 PID。这次运气好，机器上正好没有 PID 8000 的进程，只报了一句 `No such process`；如果当时恰好有个无关进程占着 PID 8000，我就顺手把它杀了。正确顺序永远是：`sudo ss -tulpn | grep 8000` → 从 `users:(("python3",pid=9025,fd=3))` 里**读出 PID** → `kill 9025`。

**4）`apt install net-tools` 没加 sudo。**

非 root 装不了包，这条是失败的。而 `netstat -tunlp` 想看进程名也必须 root，所以两条都得 `sudo`。后来确认 netstat 早在 10-21 就装好了，不用重装。

**5）`curl -c-O URL` 生成了一个名叫 `-O` 的垃圾文件。**

`-c` 是「cookie 文件」，它把紧跟其后的 `-O` 当成了文件名，于是写出一个 131 字节、抬头是 `# Netscape HTTP Cookie File` 的文件叫 `./-O`；同时 `-O` 本身失效，那 38 MB 的二进制直接喷到了终端上。curl 的短选项**不能像 gcc 那样黏在一起**，要写成 `curl -O URL`。这两个文件（`~/-O` 和 `~/ls-lR.gz`）要删掉。

**6）`pgrep -f https.server` 一直查不到东西，我差点以为服务挂了。**

多打了一个 `s`。而且 pattern 里的 `.` 是**正则通配符**不是字面点，所以 `https.server` 要求文本里存在 `https`+任意字符+`server`，而实际进程命令行是 `python3 -m http.server`，压根没有 `https` 这个子串，必然匹配不到。`pgrep` 查不到 ≠ 服务没跑，先怀疑自己的 pattern。这个错这几天犯了三次。

**7）`pidof mysqld；` 用的是中文全角分号。**

bash 不认全角标点，`；ps -ef` 会被当成参数而不是两条命令。输入法切英文这个动作，在敲命令的终端里是必须的前置动作。
