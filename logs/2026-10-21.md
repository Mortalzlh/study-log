## 卡住的地方

**1）装 WSL 时下载只有 48 KB/s，查出来是系统代理在拖慢，不是加速。**

`netstat -ano | findstr <wsl.exe的PID>` 显示 `wsl.exe` 唯一的连接就是打到 `127.0.0.1:4088`，也就是**它读系统代理**。把系统代理关掉重跑，几十秒装完。同一时间实测对照：

| 走法 | 速度 |
| --- | --- |
| 走 4088 代理下 Ubuntu 镜像 | 48 KB/s |
| 完全直连拉清华 PyPI 的 159MB 文件 | 11 MB/s |
| 直连 github.com | 1.2s 返回 200 |
| 直连微软 Azure 下载站 | 0.7s |

这推翻了我上午记的那条结论。上午的记录（保留原文，因为它当时确实是这样）：

```bash
git config --global http.proxy  http://127.0.0.1:4088
git config --global https.proxy http://127.0.0.1:4088
```

正确的判断顺序应该是：**先测直连，再决定要不要走代理**，而且不要写全局 `http.proxy`，需要时用单次 `-c` 传参。这个代理软件的节点全在国内（阿里云、腾讯云），对微软和 Ubuntu 的 CDN 反而绕远路。

验证连通性：`git ls-remote https://github.com/git/git.git HEAD`，能返回 commit hash 就是通的。

**2）把主数据污染了，标准答案当场漂移。**

2.5 要练 `tail -f` 实时看日志增长，我直接往 `access.log` 里 `echo >>` 追加了一行。结果：

- `access.log` 从 10000 行变 10001 行，`md5sum` 从 `5fa34e61...` 变 `c78b5101...`
- 2.4 那道题的答案从 **7** 变成 **8**：追加的那行没有第 9 个字段，`awk '{print $9}'` 对它输出**空字符串**，空串自己成了第 8 组
- `stat.txt` 第一行出现 `1 ...`，那行垃圾被当成一个独立 IP 统计进去了

教训比命令本身值钱：**数据污染不报错，只让结果悄悄变形。** 如果我不知道标准答案是 7，就会以为自己 `uniq` 用错了，然后花两小时去查一个根本不存在的 bug。以后凡是会往文件里写数据的练习，一律先 `cp access.log t.log`，在副本上做。

**3）两个顺手发现的小坑。**

- `ls f*.txt` 排出来是 `f1 f10 f4 f5...`，**按字符串不按数字**。真实日志按 `.1 .2 ... .10` 滚动时，用 `ls | tail -1` 取「最新一个」会拿错。要按数字排用 `ls -v` 或 `sort -V`。
- `... | tee stat.txt | head` 里 `stat.txt` 有 32 行而不是 10 行。**`tee` 在 `head` 之前，写进文件的是全量，只有屏幕显示被截断了**。32 就是这份日志里不同 IP 的个数。
