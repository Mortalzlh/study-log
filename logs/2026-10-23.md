## 卡住的地方

**1）awk 里 `$9}]` 这个括号错敲了 4 次才改过来。**

报错信息 `mawk: fatal: cannot open file ']' for reading` 其实已经告诉你答案了——多打了个 `]`，awk 把它当文件名。下次先看报错，别急着重敲。

**2）`kill -9 <3709>` 尖括号是占位符。**

任务单里写 `<PID>` 是「这儿换成你的进程号」的记号，不是命令的一部分。bash 把 `<` 当**输入重定向**，于是报 `3709>: No such file or directory`，`kill` 压根没执行。后来 `kill -9 3710`（不带尖括号）才成功。以后凡是看到文档里 `<...>`、`[...]`、`{...}`，先问自己一句：这是语法还是记号？

**3）`./dex/null` 那条——`> /dev/null` 被拆成两段。**

重定向符号 `>` 和它的目标 `/dev/null` 分到了两条命令里，bash 把 `./dex/null` 当命令名找，报 `command not found`。这条没造成破坏（`/dev/null` 是设备文件，健康）。

**4）`s.sh` 的 shebang 多了一个斜杠。**

今天敲的是 `echo '#!/bin/bash/'>s.sh`，行尾多了个 `/`。实测两种跑法：

- `./s.sh` → `/bin/bash/: bad interpreter: Not a directory`，返回码 **126**（找到了但没法执行）
- `bash s.sh` → `s.sh: line 2: nihao: command not found`，返回码 **127**（命令找不到）

同一个文件，两种跑法连失败原因都不一样。修掉它：`echo '#!/bin/bash' > s.sh && echo 'echo hi' >> s.sh && chmod +x s.sh && ./s.sh`，要看到 `hi`。

**5）`cat /proc/<pid>/cmdline` 输出粘连。**

`python3-mhttp.server` 看起来像命令出错，其实是参数之间用 **NUL（`\0`）分隔**，终端把 NUL 吞掉，于是 `python3` `-m` `http.server` 粘成一坨；而且结尾没有换行，所以提示符被拽到同一行。规范写法：

```bash
tr '\0' ' ' < /proc/$(pgrep -f http.server)/cmdline; echo
```
